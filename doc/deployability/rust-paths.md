## 2. Guards: what Rust checks vs TS
- xsd_guards.rs: NCName for process/element/flow ids (/^[A-Za-z_][A-Za-z0-9_.-]*$/), retries /^(=.+|\d+)$/. Mirrors packages/core/src/bpmn/xsd-guards.ts exactly (same messages, JSON.stringify twin). Drift: TS also checks booleans cancelActivity/isInterrupting/multiInstance.isSequential; Rust has no twin (typed Option<bool>) - intentional. TS assertXsdValues is on BpmnProcess; Rust applies it only to new builds.
- Data is shared via spec/*.json -> scripts/spec-gen.mjs -> TS generated + bpmnkit_spec (CI `spec-gen --check`). So rule tables cannot drift; logic is hand-ported.
- bpmnkit-compat (crates/bpmnkit-compat/src/compat/{mod,contents,agent,feel,no_loop,pattern}.rs, 7.4k lines vs TS packages/core/src/bpmn/camunda-compat*.ts 2.9k). analyze_camunda_compat mod.rs:369: target = explicit version else modeler:executionPlatformVersion; none => no findings; >=8.2 skips non-executable processes. Checks: process (listeners, template, no-zeebe-properties, versionTag, no-multiple-none-start-events), collapsed subprocess (DI isExpanded), per-element type support, implementation (task definition/script/called decision), timers 2x2 table, message/signal/error/escalation refs, link events, execution/task listeners & duplicates, io-mapping, loop characteristics, ad-hoc, forms (user-task/start-event), priority/schedule, FEEL built-in availability (feel.rs), agent contract (fromAi, tool output key), connector props/inbound, secrets. 65 rule names in spec/compat-rules.json; all but 3 (agent-tool-documentation, executable-process, feel) appear in both TS and Rust source by name; those 3 are deliberately not emitted (README: replaced by agentic/tool-no-description, deploy/process-not-executable, feel-syntax/parse-error). Parity pinned by conformance/compat/* (versions default, 8.0, 8.2, 8.5, 8.6, 8.8, 8.10, 1.0.. ) compared structurally.
- bpmnkit-lint: lint_diagram (lint.rs:138) = optimize() [crates/bpmnkit-lint/src/optimize/mod.rs:92: categories feel, feel-syntax, flow, naming, task-reuse, pattern, data-flow, deploy+connector, agentic; plus compat when deploy on or version pinned] + bpmnlint rules + optional .bpmnlintrc. Engine categories (deploy, connector, agentic) dropped when model names no execution platform (modeler:executionPlatform; "cloud"=CamundaCloud) unless force_engine_rules.
  - deploy/*: process-not-executable, service-task-no-type, call-activity-no-process, message-start-no-name, message-catch-no-correlation, event-definition-no-id; connector/missing-required (needs resolver).
  - flow/*: dead-end, empty-subprocess, mixed-gateway, multi-incoming-task, no-end-event, no-start-event, redundant-gateway, unreachable. feel/*: complex-condition, complex-io-mapping, duplicate-expression, empty-condition, missing-default-flow. naming/*, pattern/* (15 incl. duplicate-job-type, http-no-error-boundary, timer-duration-zero), agentic/* (5).
  - bpmnlint native (bpmnlint_rules.rs, 1590 lines; spec/lint-rules.json 28 rules): ad-hoc-sub-process, conditional-event, conditional-flows, end-event-required, event-based-gateway, event-sub-process-typed-start-event, fake-join, global, label-required, link-event, no-bpmndi, no-complex-gateway, no-disconnected, no-duplicate-sequence-flows, no-gateway-join-fork, no-implicit-end/split/start, no-inclusive-gateway, no-overlapping-elements, single-blank-start-event, single-event-definition, standard-size, start-event-required, sub-process-blank-start-event, superfluous-gateway/label/termination. Presets correctness/recommended.
  - Also lint_dmn, lint_form (CheckFinding). Parity pinned by conformance/lint, conformance/optimize (incl. fixes' resulting XML).
- Gap relative to Zeebe: neither lint nor compat checks XSD enumeration/datatype validity on parsed docs; builder only checks ids+retries.

## 4. Conformance + CI
- conformance/ is a corpus; TS is oracle. `pnpm conformance:record` (scripts/conformance-record.mjs) runs vitest `conformance` in @bpmnkit/feel, @bpmnkit/core, @bpmnkit/engine with CONFORMANCE_RECORD=1, rewriting expected/*. CI: `git diff --exit-code conformance/`. In normal vitest runs TS fails on drift; Rust runner crates/bpmnkit-conformance (cargo test --workspace) reads the same files and compares (JSON structural; XML/BPMN byte-for-byte; FEEL numbers by value or 15 sig digits; layout within tolerance). conformance/pending.json lists known-unrepresentable cases (1 entry).
- Kinds: feel/*.jsonl, bpmn/<case>/{input.bpmn,expected/model.json,roundtrip.bpmn}, form, dmn (+evaluate.json), lint, optimize (findings + fixes xml), compat (findings per version), migrate (7to8/8to7, juel.jsonl), layout, builder (case.json script of method calls; expected model.json+output.bpmn or error.txt/warning.txt; xsd-* and export-* cases pin guards), text, compact.
- NO case asserts "deployable"/Zeebe validity of output. Closest: builder export-* (Bpmn.export validate warn/error -> lint deploy errors), xsd-* cases, optimize/deploy-* and compat/* findings. reebe is not referenced by any conformance runner (reebe DMNs were only copied in as inputs).
- CI (.github/workflows): ci.yml jobs `generated` (spec-gen --check, build feel+core, conformance-ts diff), `ci` (JS), `conformance-rs` (cargo fmt, clippy -D warnings, cargo test --workspace, benches compile, crates metadata), `msrv-rs`; reebe.yml (path-filtered + weekly; apps/reebe cargo tests with postgres:16-alpine service container; sqlite tests); dmn-tck.yml, fuzz-nightly.yml (bpmnkit-fuzz differential), bench-nightly.yml; others are deploy/release. No Zeebe/c8run/testcontainers/Camunda docker image anywhere; no Java/setup-java in workflows. Only docker service = Postgres.
- Sandbox: /usr/bin/docker (client 29.9.2) present but daemon NOT running (no /var/run/docker.sock); java and mvn present (/opt/maven/bin/mvn; JAVA_TOOL_OPTIONS proxy set). Real Zeebe would need docker daemon or a downloaded Zeebe/c8run jar + network via proxy (not verified).
