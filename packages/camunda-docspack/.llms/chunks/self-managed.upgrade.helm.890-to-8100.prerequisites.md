# Upgrade Camunda 8.9 to 8.10 using Helm — Prerequisites

Before you upgrade, make sure you meet these prerequisites:

| Prerequisite                      | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| :-------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirm `8.9.x` baseline          | Check that your deployment runs an `8.9.x` version before you upgrade to 8.10. If you upgrade from a version earlier than 8.9, upgrade one minor at a time. See [upgrading from an earlier version](https://docs.camunda.io/docs/next/self-managed/upgrade/index#upgrading-from-an-earlier-version). We strongly recommend that you upgrade to the latest available `8.9.x` patch first, for fix coverage.                                                                                                         |
| Confirm Helm CLI version          | Camunda 8.10 (chart 15.x) supports Helm CLI v3 (3.10 or later) and v4. See [Helm CLI support and chart compatibility](https://docs.camunda.io/docs/next/self-managed/deployment/helm/operational-tasks/helm-v4#camunda-helm-chart-compatibility) and [Move from the Helm v3 CLI to v4](https://docs.camunda.io/docs/next/self-managed/deployment/helm/operational-tasks/moving-helm-v3-to-v4).                                                                                                                                                   |
| Confirm upgrade eligibility       | Review [Prepare for upgrade](https://docs.camunda.io/docs/next/self-managed/upgrade/prepare-for-upgrade) to check upgrade eligibility and to check infrastructure compatibility for 8.10.                                                                                                                                                                                                                                                                                                                          |
| Confirm Helm chart support        | Review the Camunda Helm chart [version matrix](https://helm.camunda.io/camunda-platform/version-matrix/) to find the chart version that deploys 8.10. The matrix also shows the Helm CLI versions that this chart version was released and tested with. Check your Kubernetes version against the [supported environments](https://docs.camunda.io/docs/next/reference/supported-environments).                                                                                                                    |
| Migrate bundled Bitnami subcharts | If your 8.9 release uses `identityKeycloak`, `identityPostgresql`, `webModelerPostgresql`, or `elasticsearch`, migrate to externally managed services. Do this while you still run 8.9, before you upgrade. Chart 15.x no longer deploys these subcharts. See [Migrate from Bitnami charts](https://docs.camunda.io/docs/next/self-managed/deployment/helm/operational-tasks/migration-from-bitnami/index).                                                                                                        |
| Backups                           | Create backups of your Camunda data. Check the backups. [Backup and restore](https://docs.camunda.io/docs/next/self-managed/operational-guides/backup-restore/backup-and-restore) covers Zeebe, Operate, Tasklist, Admin, and Optimize. To create a backup of the Web Modeler database, follow [Hub database backup](#back-up-the-hub-database). Create backups of the Management Identity and Keycloak databases with your database vendor's tooling. The Backup and restore guide doesn't cover these databases. |
| Check your `values.yaml`          | Review your existing `values.yaml` for [keys that chart 15.x rejects](#remove-keys-rejected-by-chart-15x), [deprecated Helm keys](#deprecated-application-configuration-helm-keys), and [changed chart defaults](#review-changed-chart-defaults).                                                                                                                                                                                                                                    |
| Plan the Camunda Hub migration    | If your release runs Web Modeler, plan a maintenance window. The Hub database migration isn't backward compatible. The migration requires you to stop all Web Modeler workloads. The upgrade also removes the Console Deployment, because Hub replaces Console. See [Migrate Web Modeler and Console to Hub](#migrate-web-modeler-and-console-to-camunda-hub).                                                                                                                       |
| Test upgrade                      | Test the upgrade in a non-production environment. Use a copy of your production configuration.                                                                                                                                                                                                                                                                                                                                                                                       |
