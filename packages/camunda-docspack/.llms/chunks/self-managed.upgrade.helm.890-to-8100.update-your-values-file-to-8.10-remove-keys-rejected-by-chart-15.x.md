# Upgrade Camunda 8.9 to 8.10 using Helm — Update your values file to 8.10 — Remove keys rejected by chart 15.x

Chart 15.x rejects removed values before it changes any workloads. Update or remove these values before you upgrade:

| Removed key                                       | Replacement or action                                                                                                                                                                                                                                                                                                                       |
| :------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `global.ingress.host`                             | Use `global.host`.                                                                                                                                                                                                                                                                                                                          |
| `global.identity.keycloak.auth.existingSecret`    | Use `global.identity.keycloak.auth.secret.existingSecret`. Also set `global.identity.keycloak.auth.secret.existingSecretKey`. In chart 14.x, the default value of the key was `admin-password`. Chart 15.x has no default. Without the key, Management Identity receives an empty Keycloak admin password.                                  |
| `global.identity.keycloak.auth.existingSecretKey` | Use `global.identity.keycloak.auth.secret.existingSecretKey`.                                                                                                                                                                                                                                                                               |
| `global.elasticsearch.*`                          | Use `optimize.database.elasticsearch.*` for Optimize. Use `orchestration.data.secondaryStorage.elasticsearch.*` for the Orchestration Cluster. See the migration mapping below.                                                                                                                                                             |
| `global.opensearch.*`                             | Use `optimize.database.opensearch.*` for Optimize. Use `orchestration.data.secondaryStorage.opensearch.*` for the Orchestration Cluster. See the migration mapping below.                                                                                                                                                                   |
| `orchestration.profiles.identity`                 | Use `orchestration.profiles.admin`.                                                                                                                                                                                                                                                                                                         |
| `webModeler.restapi.externalDatabase.user`        | Use `camundaHub.restapi.externalDatabase.username`.                                                                                                                                                                                                                                                                                         |
| `identityKeycloak`, `identityPostgresql`          | Migrate Keycloak and the Management Identity database to externally managed services while you're still on 8.9. Chart 15.x doesn't render the bundled workloads, so Helm removes their StatefulSets during the upgrade. See [Migrate from Bitnami charts](https://docs.camunda.io/docs/next/self-managed/deployment/helm/operational-tasks/migration-from-bitnami/index). |
| `webModelerPostgresql`                            | Migrate the Camunda Hub database to external PostgreSQL while you're still on 8.9. Also configure `camundaHub.restapi.externalDatabase`.                                                                                                                                                                                                    |
| `elasticsearch`                                   | Migrate to external Elasticsearch or OpenSearch while you're still on 8.9. Also configure the secondary storage values of each component.                                                                                                                                                                                                   |

The chart rejects these keys whenever they're in your values file, even when their block only sets `enabled: false`, such as `elasticsearch: {enabled: false}`.

Two checks apply only to a deployed component. The check for `orchestration.profiles.identity` applies when the chart deploys the Orchestration Cluster. The check for `webModeler.restapi.externalDatabase.user` applies when the chart deploys Hub. Remove the whole block from your values file.

#### Migrate `global.elasticsearch` and `global.opensearch`

Chart 14.x deprecated the `global.elasticsearch.*` and `global.opensearch.*` trees, and chart 15.x removes them. If you set any key under them, the render fails with `[camunda][error] The Helm values file key "global.elasticsearch" has been removed.` A message that names the replacement keys follows.

The table shows the Elasticsearch keys. The OpenSearch keys mirror the Elasticsearch keys, except `external` and `disableExporter`, which exist only for Elasticsearch. Map your values as follows:

| Removed key                                                                    | Replacement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| :----------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `global.elasticsearch.enabled`                                                 | Use `optimize.database.elasticsearch.enabled` (Optimize and the legacy Zeebe exporter), `orchestration.data.secondaryStorage.type: elasticsearch`, or both. If you enable Optimize, set `optimize.database.elasticsearch.enabled: true`. The secondary storage type alone doesn't configure the Optimize database or the exporter that writes the indices that Optimize reads. The chart renders the legacy Zeebe exporter when you enable Optimize with `optimize.database.elasticsearch.enabled: true` and the cluster doesn't span more than one region or zone. The chart also renders the exporter when you set `orchestration.exporters.zeebe.enabled: true` with Elasticsearch secondary storage. |
| `global.elasticsearch.external`                                                | `optimize.database.elasticsearch.external`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `global.elasticsearch.url.*`                                                   | Use `optimize.database.elasticsearch.url.{protocol,host,port}`, the full-URL string `orchestration.data.secondaryStorage.elasticsearch.url`, or both. When `orchestration.data.secondaryStorage.elasticsearch.url` is empty, the Orchestration Cluster uses the Optimize URL. Set the URL explicitly. The Optimize default, `http://<RELEASE>-elasticsearch:9200`, is the address of the bundled subchart that chart 15.x no longer deploys.                                                                                                                                                                                                                                                             |
| `global.elasticsearch.auth.*`                                                  | Set both `optimize.database.elasticsearch.auth.*` and `orchestration.data.secondaryStorage.elasticsearch.auth.*`. The secondary storage of the Orchestration Cluster doesn't reuse the Optimize credentials, even when the Orchestration Cluster reuses the Optimize URL. When Optimize owns the legacy Zeebe exporter, the exporter authenticates with `optimize.database.elasticsearch.auth.*`. The exporter does this only when `optimize.database.elasticsearch.external` is `true`.                                                                                                                                                                                                                 |
| `global.elasticsearch.tls.secret.*`, `global.elasticsearch.tls.existingSecret` | Use `global.tls.caBundle.secret` with a PEM CA bundle. The per-component `optimize.database.elasticsearch.tls.secret.*` and `orchestration.data.secondaryStorage.elasticsearch.tls.secret.*` keys still work, but chart 15.x deprecates them. See [move per-component truststores to `global.tls.caBundle`](#move-per-component-truststores-to-globaltlscabundle).                                                                                                                                                                                                                                                                                                                                       |
| `global.elasticsearch.tls.jks.secret.*`                                        | Chart 15.x removes this key together with the truststore password injection. Use `global.tls.caBundle.secret` (PEM). Alternatively, pass `-Djavax.net.ssl.trustStorePassword=...` in the `javaOpts` of the component. To keep the password in a Secret, load the Secret with the `envFrom` of the component. Then reference the key of the Secret as `$(KEY)` in `javaOpts`. The chart renders `JAVA_TOOL_OPTIONS` before the component's `env` entries, so a `$(VAR)` reference to a variable defined in `env` doesn't expand. A reference to a variable that `envFrom` loads does expand.                                                                                                              |
| `global.elasticsearch.prefix`                                                  | Use `optimize.database.elasticsearch.prefix`. Chart 15.x also deprecates this key. See [Optimize](#optimize). The legacy Zeebe exporter writes its indices with `orchestration.exporters.zeebe.index.prefix`. If this key is unset, the exporter uses `optimize.database.elasticsearch.prefix`. If that key is also unset, the exporter uses `zeebe-record`.                                                                                                                                                                                                                                                                                                                                             |
| `global.elasticsearch.clusterName`                                             | The chart no longer renders this key. The application default is identical. If you need this setting, set `camunda.data.secondary-storage.elasticsearch.cluster-name` in `orchestration.extraConfiguration`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `global.elasticsearch.disableExporter`                                         | You don't need a replacement. The key had no effect.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `global.elasticsearch.tls.enabled`                                             | You don't need a replacement. The key had no effect. The connection uses TLS when the URL scheme is `https`. `tls.secret.*` and `global.tls.caBundle` only supply the CA that the component trusts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `global.opensearch.aws.enabled`                                                | The key applies only to OpenSearch and has no Elasticsearch equivalent. Use `optimize.database.opensearch.aws.enabled`, `orchestration.data.secondaryStorage.opensearch.aws.enabled`, or both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
