# Property reference — Data - primary storage — `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP`

| Property                                                | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Default value | Overridable per Physical Tenant                                                   |
| :------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :-------------------------------------------------------------------------------- |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_STORE`              | Sets the backup store type.Supported values are `NONE`, `S3`, `GCS`, `AZURE`, and `FILESYSTEM`.`NONE`: No backup store is configured, and no backup is taken.`S3`: Use any [Amazon S3-compatible storage](https://docs.aws.amazon.com/AmazonS3/latest/API/Type_API_Reference.html).`GCS`: Use [Google Cloud Storage](https://cloud.google.com/storage/).`AZURE`: Use [Azure Storage](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction).`FILESYSTEM`: Use filesystem storage.Note: This configuration applies to the backup of primary storage. | `NONE`        | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_CONTINUOUS`         | Enables or disables the continuous backups feature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `false`       | Needs verification ([#9795](https://github.com/camunda/camunda-docs/issues/9795)) |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_REQUIRED`           | Forces the backup scheduler mechanism to be properly configured during broker startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | `false`       | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_SCHEDULE`           | The interval at which a primary storage backup is taken. Can be a CRON expression, an ISO-8601 duration, or `none`. For example, every 5 minutes would be `0 */5 * * * *` or `PT5M`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `-`           | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_CHECKPOINTINTERVAL` | The interval at which checkpoints are ingested into the log stream. Uses an ISO-8601 duration, for example `PT5M`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | `-`           | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_OFFSET`             | Offset for the generated backup identifiers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | `-`           | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_READTIMEOUT`        | The maximum duration for reading a response from an already-established connection to the backup store.A single request that exceeds this timeout fails and can be retried. For `S3`, retries are attempted as long as `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_S3_APICALLTIMEOUT` is not exhausted.Applies to the `S3`, `GCS`, and `AZURE` stores. For `AZURE`, this value also caps how long the client waits for the server to start replying.When not set, the default of the underlying store client applies: 30s for `S3`, 20s for `GCS`, and 60s for `AZURE`.Accepts a duration, for example `30s` or `PT30S`.                        | `-`           | Yes                                                                               |
| `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_WRITETIMEOUT`       | The maximum duration for writing a request to an already-established connection to the backup store.A single request that exceeds this timeout fails and can be retried, with the same retry semantics as `CAMUNDA_DATA_PRIMARYSTORAGE_BACKUP_READTIMEOUT`.Applies to the `S3`, `GCS`, and `AZURE` stores. When not set, the default of the underlying store client applies: 30s for `S3` and 60s for `AZURE`. `GCS` has no write timeout by default, so a stalled upload can block a backup indefinitely.Accepts a duration, for example `30s` or `PT30S`.                                                                                    | `-`           | Yes                                                                               |
