# Prepare for upgrade — Back up database

When upgrading to Camunda 8.10, your Web Modeler/Camunda Hub data will be [migrated](https://docs.camunda.io/docs/next/self-managed/upgrade/components/890-to-8100#data-migration) to the [new structure](https://docs.camunda.io/docs/next/reference/announcements-release-notes/8100/whats-new-in-810#new-file-structure-and-requirements). Camunda recommends you create a backup before the migration to ensure your data is recoverable in its original state if anything goes wrong. If you notice anything unexpected after the migration, contact support.

## Review pre-upgrade actions required for Camunda 8.10

This section lists actions you must complete or review before upgrading to Camunda 8.10.

| Impact                                                                                       | Area                                        | What's changed / Action required                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| :------------------------------------------------------------------------------------------- | :------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Action required  | Helm chart: Secret configuration            | Deprecated secret keys are removed in 8.10.If your `values.yaml` uses old key paths (for example, `global.license.key`, `*.existingSecret` at legacy paths), update them to the new `*.secret.existingSecret` pattern before upgrading.Additionally, `global.secrets.autoGenerated` is removed. All secrets must be explicitly provided. See [Helm chart: Deprecated secret keys removed](https://docs.camunda.io/docs/next/reference/announcements-release-notes/8100/8100-announcements#helm-chart-deprecated-secret-keys-removed) and [Secret management](https://docs.camunda.io/docs/next/self-managed/deployment/helm/configure/secret-management). |
| Action required  | Helm chart: bundled Elasticsearch subchart  | The chart no longer bundles an Elasticsearch subchart.Provide an externally managed Elasticsearch or OpenSearch and point the chart at it via `orchestration.data.secondaryStorage.elasticsearch/opensearch.*` (and `optimize.database.elasticsearch/opensearch.*` when Optimize is enabled).You must also set `orchestration.data.secondaryStorage.type` explicitly (no default), whether you use Elasticsearch, OpenSearch, or RDBMS.                                                                                                                                                                                                                                                  |
| Check         | Helm chart: REST port                       | The default HTTP port for the Orchestration Cluster changed from 8090 to 8080. Check and update any hardcoded port references in network policies, Ingress rules, or monitoring.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| If customized | Web Modeler: Removed `webapp` component     | Web Modeler's separate `webapp` component has been removed, and its functionality is now integrated into the `restapi` component. If you use custom configuration settings for the `webapp` or replace the `restapi` configuration using `webModeler.restapi.configuration`, you need to update your configuration. See the [component upgrade guide](https://docs.camunda.io/docs/next/self-managed/upgrade/components/890-to-8100#migrate-webapp-configuration).                                                                                                                                                                                                        |
| If customized | Web Modeler: Logging framework              | Web Modeler `restapi` now uses Apache Log4j 2 instead of Logback. If you have a custom Logback configuration, migrate it before upgrading. See the [Log4j migration guide](https://logging.apache.org/log4j/2.x/migrate-from-logback.html).                                                                                                                                                                                                                                                                                                                                                                                                |
| If customized | Web Modeler: Embedded web server            | Web Modeler now uses Apache Tomcat instead of Undertow. If you have custom Undertow configuration (`server.undertow.*`), migrate it to Tomcat equivalents. See the [component upgrade guide](https://docs.camunda.io/docs/next/self-managed/upgrade/components/890-to-8100#embedded-web-server) for a property mapping table.                                                                                                                                                                                                                                                                                                                                                                 |
| If customized | Orchestration Cluster: Physical Tenants | Upgrading a single-tenant cluster requires no action. Existing configuration becomes the `default` Physical Tenant automatically, and existing API and web app URLs continue to work.If you add any `camunda.physical-tenants.default.*` override, that tenant must also declare `providers.assigned` or the cluster fails to start. See the [component upgrade guide](https://docs.camunda.io/docs/next/self-managed/upgrade/components/890-to-8100#physical-tenants). |
| Recommended          | Helm chart: TLS secret pattern              | Legacy TLS secret configuration (`*.tls.existingSecret`) is deprecated. Migrate to `*.tls.secret.existingSecret`. The legacy keys still work in 8.10.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Action required  | Helm chart: Bitnami subcharts               | The Bitnami-based subcharts (`identityPostgresql`, `identityKeycloak`, `webModelerPostgresql`, `elasticsearch`) are removed in 8.10. Provide PostgreSQL, Elasticsearch or OpenSearch, and Keycloak through managed services or Kubernetes operators before upgrading. See [operator-based infrastructure](https://docs.camunda.io/docs/next/self-managed/deployment/helm/configure/operator-based-infrastructure).                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Action required  | Helm chart: secondary storage global config | `global.elasticsearch.*` and `global.opensearch.*` (deprecated in 8.9) are removed in 8.10. Setting any key under them fails `helm install`/`helm upgrade` with an error naming the replacement. Migrate to `orchestration.data.secondaryStorage.elasticsearch/opensearch.*` and `optimize.database.elasticsearch/opensearch.*`. See the [8.9 to 8.10 upgrade guide](https://docs.camunda.io/docs/next/self-managed/upgrade/helm/890-to-8100).                                                                                                                                                                                                                              |
| Recommended          | Helm chart: Orchestration profile           | `orchestration.profiles.identity` is deprecated and renamed to `orchestration.profiles.admin`. The chart auto-migrates the old key with a deprecation warning. Update your values file to use the new key.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Recommended          | Helm chart: Keycloak auth secret            | `global.identity.keycloak.auth.existingSecret` and `existingSecretKey` are deprecated. Migrate to `global.identity.keycloak.auth.secret.existingSecret` and `existingSecretKey`. Legacy keys still work in 8.10 via normalizers. See [Secret management](https://docs.camunda.io/docs/next/self-managed/deployment/helm/configure/secret-management).                                                                                                                                                                                                                                                                                                                     |
