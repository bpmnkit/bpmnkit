# Property reference — Data - primary storage — `camunda.data.primary-storage.backup`

| Property                                                  | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Default value | Overridable per Physical Tenant                                                   |
| :-------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :-------------------------------------------------------------------------------- |
| `camunda.data.primary-storage.backup.store`               | Set the backup store type.Supported values are `NONE`, `S3`, `GCS`, `AZURE`, `FILESYSTEM`.`NONE`: No backup store is configured and no backup will be taken.`S3`: Use any [Amazon S3 compatible storage](https://docs.aws.amazon.com/AmazonS3/latest/API/Type_API_Reference.html).`GCS`: Use [Google Cloud Storage](https://cloud.google.com/storage/).`AZURE`: Use [Azure Storage](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction).`FILESYSTEM`: Use filesystem storageNote: This configuration applies to the backup of primary storage. | `NONE`        | Yes                                                                               |
| `camunda.data.primary-storage.backup.continous`           | Enables or disables the continuous backups feature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `false`       | Needs verification ([#9795](https://github.com/camunda/camunda-docs/issues/9795)) |
| `camunda.data.primary-storage.backup.required`            | Forces the backup scheduler mechanism to be properly configured during broker startup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `false`       | Yes                                                                               |
| `camunda.data.primary-storage.backup.schedule`            | The interval at which a primary storage backup is taken. Can be a CRON expression, ISO8601 duration or `none`. For example, every 5 minutes would be `0 */5 * * * *` and `PT5M` respectively.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | `-`           | Yes                                                                               |
| `camunda.data.primary-storage.backup.checkpoint-interval` | The interval at which checkpoints are ingested in the logstream. ISO8601, for example `PT5M` duration.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `-`           | Yes                                                                               |
| `camunda.data.primary-storage.backup.offset`              | Offset for the generated backup identifiers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | `-`           | Yes                                                                               |
| `camunda.data.primary-storage.backup.read-timeout`        | The maximum duration for reading a response from the backup store.A single request that exceeds this timeout fails and can be retried. Applies to the `S3`, `GCS`, and `AZURE` stores.When not set, the default of the underlying store client applies: 30s for `S3`, 20s for `GCS`, and 60s for `AZURE`.Accepts a duration, for example `30s` or `PT30S`.                                                                                                                                                                                                                                                                                   | `-`           | Yes                                                                               |
| `camunda.data.primary-storage.backup.write-timeout`       | The maximum duration for writing a request to the backup store. Applies to the `S3`, `GCS`, and `AZURE` stores.When not set, the default of the underlying store client applies: 30s for `S3` and 60s for `AZURE`. `GCS` has no write timeout by default.Accepts a duration, for example `30s` or `PT30S`.                                                                                                                                                                                                                                                                                                                                          | `-`           | Yes                                                                               |
