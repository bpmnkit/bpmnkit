# Camunda back up and restore — Considerations — Backup IDs

When using Elasticsearch or OpenSearch as secondary storage, each component backup is identified by a user-supplied integer backup ID. The backup ID must be greater than the ID of any previous backup. Using Unix timestamps as backup IDs is a common practice to ensure uniqueness and chronological order. When using RDBMS as secondary storage, backup IDs are auto-generated by the cluster and do not need to be managed manually.

The steps outlined on this page are generally applicable for any kind of deployment but might differ slightly depending on your setup.
