# Admin in Self-Managed

Learn how Admin is bundled with your default orchestration cluster.

Admin (formerly Orchestration Cluster Identity) is included by default with the [Orchestration Cluster](https://docs.camunda.io/docs/next/self-managed/reference-architecture/reference-architecture#orchestration-cluster) in all Self-Managed installation methods. Within a cluster, Admin provides unified, cluster-level identity management and authorization. See [how identity works in Camunda](https://docs.camunda.io/docs/next/self-managed/components/identity/how-identity-works) for how Admin relates to Management Identity and which one to configure.

**Note: Profile transition**
In Camunda 8.9, the `admin` Spring profile replaces the `identity` profile. Both profiles work interchangeably in 8.9. The `identity` profile is deprecated and will be removed in a future version.

The following guides cover Admin configuration in Self-Managed environments. For information on using and managing Admin, see [Admin user guides](https://docs.camunda.io/docs/next/components/admin/admin-introduction).
