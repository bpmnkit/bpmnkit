# Dual-Region — Architecture — Component requirements

|                                     Component | Mode                                                    | Requirement                           | Function                                                                                                                                                                                                                                                                                                         | Data loss risk                                                                                                                                                                                                                  |
| --------------------------------------------: | :------------------------------------------------------ | :------------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Orchestration Cluster** |                                                         |                                       |                                                                                                                                                                                                                                                                                                                  |                                                                                                                                                                                                                                 |
|                                         Zeebe | Active-active                                           | All brokers in both regions must run  | Leaders and followers distributed across regionsContinuous replication via Raft protocolBoth regions required for quorum maintenance                                                                                                                                         | Can handle region failure without data loss when properly configured                                                                                                                                                            |
|                                         Admin | Active-active                                           | Embedded in the Orchestration Cluster | Provides unified, cluster-level identity management and authorization                                                                                                                                                                                                                          | Can handle region failure without data loss                                                                                                                                                                                     |
|                                       Operate | Active-active with v2 API (active-passive with v1)      | Embedded in the Orchestration Cluster | Both regions maintain synchronized data stateBoth regions serve users when using v2 API**Region-specific data**: Uncompleted batch operations only when using v1 API                                                                                                         | Data loss possible only when using v1 API, as changes are isolated to the initiated region                                                                                                                                      |
|                                      Tasklist | Active-active with Tasklist V2 (active-passive with v1) | Embedded in the Orchestration Cluster | Both regions maintain synchronized data stateBoth regions serve users when using Tasklist V2**Region-specific data**: Task assignments only when using v1 API                                                                                                                | Data loss possible only when using v1 API, as changes are isolated to the initiated region                                                                                                                                      |
|         **Elasticsearch** | Active-active                                           | Both clusters must run                | Independent clusters in each regionThe Camunda Exporter writes identical data to both continuously and directlyThe Camunda Exporter's dual-write mechanism (not Elasticsearch replication) maintains data consistencyThe clusters don't communicate with each other | If the secondary Elasticsearch cluster is unreachable, the Camunda Exporter position stalls and [flow control](https://docs.camunda.io/docs/next/self-managed/operational-guides/configure-flow-control) applies backpressure, throttling user commands cluster-wide |
