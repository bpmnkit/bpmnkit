# Size clusters with Physical Tenants — Size secondary storage

Secondary storage is usually the first bottleneck as you add tenants. Size a shared database instance or cluster for the combined load of all its tenants. Size a dedicated instance for its own tenant, using the general [secondary storage](https://docs.camunda.io/docs/next/components/best-practices/architecture/sizing-your-environment#secondary-storage) guidance.
