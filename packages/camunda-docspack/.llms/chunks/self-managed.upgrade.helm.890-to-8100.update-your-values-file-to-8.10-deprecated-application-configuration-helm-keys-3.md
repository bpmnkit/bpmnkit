# Upgrade Camunda 8.9 to 8.10 using Helm — Update your values file to 8.10 — Deprecated application configuration Helm keys (3)

#### Connectors

Move these keys to `connectors.extraConfiguration`:

| Deprecated key                                    | Notes                                   |
| :------------------------------------------------ | :-------------------------------------- |
| `connectors.logging.level."io.camunda.connector"` | `logging.level."io.camunda.connector"`. |

#### Optimize

Move these keys to `optimize.extraConfiguration`, except where the notes say otherwise. Entries marked `Native config` use Optimize's own configuration property names instead of the `camunda.*` namespace. Set these entries in `optimize.extraConfiguration` as well:

| Key                                                                           | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| :---------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `optimize.logLevel`, `optimize.upgradeLogLevel`, `optimize.esLogLevel`        | `logging.level.io.camunda.optimize`, `logging.level.io.camunda.optimize.upgrade`, and `logging.level.org.elasticsearch`. Write each logger name as one key under `logging.level`.                                                                                                                                                                                                                                                                                                  |
| `optimize.profiles`                                                           | `spring.profiles.active`.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `optimize.caches.cloudTenantAuthorizations.{maxSize,minFetchIntervalSeconds}` | Native config `caches.cloudTenantAuthorizations.maxSize` and `caches.cloudTenantAuthorizations.defaultTtlMillis`. The old `minFetchIntervalSeconds` value is a cache lifetime in milliseconds, so `defaultTtlMillis` replaces it. These caches apply to multi-tenancy.                                                                                                                                                                                                             |
| `optimize.partitionCount`                                                     | Native config `zeebe.partitionCount`.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `optimize.database.{elasticsearch,opensearch}.prefix`                         | Native config `zeebe.name`. Also set `orchestration.exporters.zeebe.index.prefix` to the same value. If `orchestration.exporters.zeebe.index.prefix` is unset, the legacy Zeebe exporter uses `optimize.database.<elasticsearch\|opensearch>.prefix`. The exporter doesn't use the `extraConfiguration` of Optimize. If you migrate only Optimize, Optimize reads indices that the exporter doesn't write.                                                                         |
| `optimize.multitenancy.enabled`                                               | Move the key to `global.multitenancy.enabled`, not to `extraConfiguration`. This is a platform-wide switch. It also enables multi-tenancy in the Orchestration Cluster and Management Identity. The chart fails the render unless `identity.enabled` and `global.identity.auth.enabled` are `true`. The chart also fails the render unless you configure `identity.externalDatabase`. See [Logical Tenants](https://docs.camunda.io/docs/next/self-managed/deployment/helm/configure/configure-logical-tenants). |

In 8.10, the chart configures Optimize through `camunda.security.*`. If the Optimize client secret sets `existingSecret` but no `existingSecretKey`, the render fails. This check applies to `global.identity.auth.optimize.secret` and to `optimize.security.authentication.oidc.secret`. See [Render fails because the Optimize client secret has no key](#render-fails-because-the-optimize-client-secret-has-no-key).

The chart doesn't configure the OIDC username and client ID claims for Optimize. Before you upgrade, set `camunda.security.authentication.oidc.username-claim` and `client-id-claim` through `optimize.extraConfiguration` to match your identity provider. Otherwise, M2M clients without an Optimize permission may see new permission errors. See [Client bearer tokens are now classified for permission checks](https://docs.camunda.io/docs/next/self-managed/upgrade/components/890-to-8100#client-bearer-tokens-are-now-classified-for-permission-checks).

The chart still renders some legacy security keys of Optimize alongside `camunda.security.*`. Because of this, Optimize logs deprecation warnings on startup, even when you set none yourself. These warnings need no change to your values file.

If you set legacy security properties of Optimize yourself, through `optimize.env` or `optimize.extraConfiguration`, Optimize maps the recognized ones at startup. Optimize also logs a deprecation warning. The chart already renders `camunda.security.authentication.oidc.*` values. These values override a mapped legacy value. Therefore, change those settings with `optimize.security.authentication.oidc.*` or with an explicit `camunda.security.*` entry in `optimize.extraConfiguration`.
