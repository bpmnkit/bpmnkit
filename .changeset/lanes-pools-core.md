Lanes, pools and message flows can be written. `ProcessBuilder.lane()` and `.participant()`, `DiagramBuilder.withAutoLayout()`; the compact format's `lanes`, `executable`, `participants` and `messageFlows` keys (`CompactLane`, `CompactParticipant`, `CompactMessageFlow`), which `reconcileCompact` checks; `lane`, `pool` and `msg` lines in process text, written by `writeProcessText` and read by `parseProcessText` and `parseProcessDelta` (with `- msg`); a `pool` line needs its bracket (`pool id[Name]`, or `pool id[]` for no name), and `lane id[]: …` is an unnamed lane, so an unnamed lane or pool reads back unnamed. Auto-layout insets nested lanes and draws the lanes of a pool with no nodes yet. New helpers: `allLanes`, `leafLanes`, `laneOf`, `assignLane`, `laneForNewNode`, `laneProblems`, `collaborationProblems`, `messageEndProblem`, `primaryProcess`, `pinPrimaryProcess`, `nameFromId`, `writableMessageLabel`, `POOL_LINE`, `MESSAGE_LINE`. `BpmnDefinitions.primaryProcessId` is written as `bpmnkit:primaryProcess` on `<definitions>` only when the file alone would lead `primaryProcess` to another process. Continuing a laned document puts a new node in its predecessor's lane; `DiagramBuilder` keeps a child process's pool and refuses a collaboration in which a process with content has no participant, or in which an id is used twice anywhere in the document (two processes declaring the same lane included). A boundary event stays in its host's lane: `assignLane` refuses to move it elsewhere and `laneProblems` reports one that is.
